@Transactional
public PaymentView pay(TenantPrincipal p, UUID orderId,
                       PayRequest req, String key) {
  tenants.lockTenant(p.tenantId());
  var done = payments.findByKey(p.tenantId(), key);
  if (done.isPresent()) return replayOrConflict(done, req);
  var order = guard.requireUnpaid(p, orderId);
  var payment = order.settle(req.method(), req.amount());
  stock.consumeForPaidOrder(order);
  audit.record(PAYMENT, order, payment);
  return payments.save(payment, key, sha256(req));
}

The KedaiMbo backend in numbers

  • Takes each payment once

    A retry with the same Idempotency-Key replays the first payment.

  • Keeps each shop’s data apart

    The tenant comes from the signed token. Another shop’s record answers 404.

  • Settles in one transaction

    The payment, its audit entry and the table are written together or not at all.

  • Rotates every refresh token

    Stored as a SHA-256 digest. A reused token ends the session.

A Telegram agent that reads KedaiMbo over gRPC

Customers ask the bot about the menu or their order. A Python service on FastAPI and LangGraph calls two read-only gRPC methods on the Spring Boot backend.

The model never sees tenant_id. The server adds it to every tool call.

Each call carries a service key, compared in constant time.

cv-resume-builder, an MCP server for ATS resumes

A Node.js server that Claude Code calls to turn a profile into a one-column A4 resume. It writes the .docx and the PDF, then checks the file before it ships.

  • One column

    No tables or pictures for the ATS to trip on.

  • Checked input

    Markup and stray bullets are refused.

  • Two languages

    Section titles in Indonesian or English.

  • .docx and PDF

    Arial, A4, margins from a preset.
